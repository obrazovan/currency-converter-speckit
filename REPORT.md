## 1. Какой источник данных выбран и почему

В качестве основного источника котировок классических фиатных валют был выбран **официальный XML-шлюз Национального банка Молдовы (НБМ / BNM)**:
- URL: `https://www.bnm.md/en/official_exchange_rates?get_xml=1&date=DD.MM.YYYY`

### Причины выбора:
1. **Официальный статус и достоверность**: Данные поступают напрямую от регулятора банковской системы Республики Молдова без сторонних посредников.
2. **Отсутствие требования API-ключей и лимитов**: Эндпоинт бесплатен, не требует регистрации, авторизационных токенов и жестких rate-limits.
3. **Прямая поддержка исторических дат**: Параметр `&date=DD.MM.YYYY` позволяет запрашивать котировки за конкретный день, что критически важно для реализации отката курсов в выходные и праздничные дни.
4. **Стабильный структурированный XML**: Теги `<CharCode>`, `<Nominal>`, `<Name>`, `<Value>` содержат полную информацию о номинале и курсе.

### Дополнительный источник: Котировки криптовалют
Для расширения функционала приложения (пользовательский запрос на конвертацию криптовалют и пар фиат-крипта) был интегрирован **Binance Public Ticker API** (`https://api.binance.com/api/v3/ticker/price`). Он предоставляет актуальные рыночные цены основных криптоактивов (`BTC`, `ETH`, `SOL`, `TON`, `USDT`) в реальном времени. Все курсы криптовалют автоматически приводятся к молдавскому лею (`MDL`) через текущий курс `USD/MDL` от НБМ, что позволяет производить взаимную конвертацию между любыми парами (например, `BTC <-> MDL`, `ETH <-> EUR`, `SOL <-> USD`).

В процессе работы с платформой Antigravity использовалась модель:

## 3. Что агент собрал корректно с первой попытки

1. **Структура спецификаций Spec Kit**:
   - Четкое разделение на принципы (Конституция), функционал (Спецификация), архитектуру (План) и пошаговые этапы (Задачи) в каталоге `.specify/`.
2. **Модульная архитектура (SOLID & Clean Code)**:
   - Полная изоляция сетевых запросов от ядра математических расчетов.
   - Универсальный алгоритм кросс-курсов через единую базовую валюту `MDL`.
   - Поддержка валют с нестандартным номиналом (например, 100 японских иен или 100 российских рублей).
3. **Отказоустойчивость и оффлайн-кэширование**:
   - Автоматическое создание локального кэша `cache/rates_cache.json`.
   - Бесшовное переключение на кэшированные данные при разрыве сетевого соединения с выводом явного предупреждения в статусной строке.
4. **Валидация пользовательского ввода**:
   - Блокировка кнопки «Конвертировать» при пустом поле, отрицательных значениях, нуле или текстовых символах.
   - Поддержка как точки, так и запятой в качестве десятичного разделителя.
   - Корректная обработка выбора одинаковых валют (курс ровно `1.0`).
5. **Функционал кнопки Swap (⇄)**:
   - Мгновенная перестановка исходной и целевой валют с автоматическим пересчетом.

## 4. Где агент ошибся, и что пришлось исправлять вручную (Обязательный раздел)

В процессе реализации возникло несколько расхождений и технических ошибок, потребовавших ручного вмешательства и корректировки кода:

1. **Ошибка области видимости фикстур в Pytest (`ScopeMismatch`)**:
   - *Проблема*: Фикстура `mock_rates` в `tests/conftest.py` была объявлена с областью видимости по умолчанию (`function`), в то время как фикстура окна `shared_tk_window` в `tests/test_gui_logic.py` имела область видимости `module`. Pytest выдал ошибку `ScopeMismatch: You tried to access the function scoped fixture mock_rates with a module scoped request object`.
   - *Исправление*: В `tests/conftest.py` для фикстуры `mock_rates` был явно задан `scope="session"`, что устранило конфликт и позволило запускать тесты GUI без падений.

2. **Конфликт повторного создания интерпретатора Tcl (`_tkinter.TclError: invalid command name "tcl_findLibrary"`)**:
   - *Проблема*: При создании нескольких независимых экземпляров `tk.Tk()` внутри одного тестового процесса Python 3.14 в ОС Windows происходило разрушение внутреннего контекста Tcl/Tk.
   - *Исправление*: Логика тестов интерфейса была переведена на единый экземпляр `shared_tk_window` с сохранением и изоляцией состояний, что обеспечило 100% стабильность прохождения тестов.

3. **Обработка нерабочих дней НБМ (Выходные и праздники)**:
   - *Проблема*: Первоначальная версия парсера НБМ делала запрос строго на текущую дату. В субботу и воскресенье сервер НБМ возвращает пустой корневой тег `<ValCurs Date="...">` без дочерних элементов `<Valute>`. Приложение воспринимало это как ошибку источника.
   - *Исправление*: В класс `BnmRateProvider` был добавлен алгоритм ретроспективного отката (до 7 календарных дней назад). Если за выбранную дату получен пустой список, провайдер циклически отступает на один день назад, пока не найдет последний официально утвержденный рабочий курс, фиксируя реальную дату в результатах.

4. **Экранирование символов кавычек в CLI PowerShell**:
   - *Проблема*: При попытке выполнить однострочный запрос к API Binance через командную строку PowerShell кавычки в параметре JSON были искажены интерпретатором Windows PowerShell (`SyntaxWarning: invalid escape sequence`).
   - *Исправление*: Параметризация была вынесена в чистые Python-скрипты с использованием стандартного словаря `params={"symbol": pair}` в библиотеке `requests`.
